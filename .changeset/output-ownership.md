'e2e': patch
---

A run only clears and writes over an `output` directory it can tell is its own: one that does not exist yet, the default `.e2e`, one holding the `.e2e-output` marker a run now leaves in any other output or a `report.json` e2e wrote, or one holding nothing but e2e's own files (`report.json`, `artifacts/`, `failures/`, the cache, and the like). `--output src`, `--output node_modules`, or any other existing directory fails with `INVALID_CONFIG` naming what is in it, where it used to delete `src/artifacts/` and overwrite `src/report.json`. The checks run on the path the filesystem opens: a symlink to the project root or outside it is refused like the path itself, and on macOS and Windows `--output TESTS` or `--output .E2E/CACHE` is refused like `tests` or `.e2e/cache`. An output a tests glob scans (`output: 'tests/results'`, or `output: 'results'` with `tests: '**/*.e2e.ts'`) is refused too, naming the `!results/**` exclusion that allows it, and `--output ..results` is no longer mistaken for a path outside the project.

`cache.dir` under `<output>/failures`, which the `markdown` reporter empties on every run, is `INVALID_CONFIG` like the other directories a run owns. A run that selects nothing (`NO_TESTS`, a `--grep` typo) leaves `<output>/artifacts` as the last run left it, and `--last-failed` after it says `which ran no tests (it ended error: NO_TESTS)` instead of `which had no failures`. `e2e mcp` sessions write their artifacts under `<output>/mcp/<target>/<attempt>/`, so an `e2e run` beside a live session no longer deletes its trace; `e2e init` adds `.e2e/mcp/` to `.gitignore`. `e2e list` takes `--output <dir>`, so `e2e list --last-failed --output out` reads the report `e2e run --output out` wrote.
