Use an existing subscription without a separate API key. Choose your plan
in `e2e init`, install dependencies, then sign in:

| Subscription | Command |
| --- | --- |
| ChatGPT Plus or Pro | `npx e2e login openai` |
| GitHub Copilot | `npx e2e login github-copilot` |
| SuperGrok or X Premium+ | `npx e2e login spacexai` |
| OpenCode Go | Set `OPENCODE_API_KEY` to the key from [opencode.ai/auth](https://opencode.ai/auth) |

Follow the terminal prompts, then run `npx e2e run`. Agent calls use your
plan's usage limits. For a new project, start with the [quickstart](/quickstart).

Claude subscriptions are not supported. To use Claude, configure an
[API provider](/models) or a model available through your Copilot plan.

## Set up an existing project

`e2e init` leaves existing configs intact. To switch an existing project to
a subscription, install the AI SDK provider package the model wraps and
replace the model in your config. The sign-in flows ship with `e2e` itself:

<Tabs>
  <Tab title="ChatGPT">
<CodeGroup>
```bash npm
npm install -D ai @ai-sdk/openai
npx e2e login openai
```

```bash pnpm
pnpm add -D ai @ai-sdk/openai
pnpm exec e2e login openai
```

```bash bun
bun add -d ai @ai-sdk/openai
bunx e2e login openai
```
</CodeGroup>

```ts title="Model setup"
import { chatgpt } from 'e2e/oauth/chatgpt';

const agent = { model: chatgpt('gpt-6-luna') };
```

Go has no sign-in command: copy the API key from
[opencode.ai/auth](https://opencode.ai/auth) and set `OPENCODE_API_KEY`.
`opencodeGo()` calls each model over the API Go serves it on: GPT, Grok, and
Muse Spark over `@ai-sdk/openai`, MiniMax and Qwen 3.8 Flash over
`@ai-sdk/anthropic` (install it for those), and the rest, such as Kimi, GLM,
and DeepSeek, over `@ai-sdk/openai-compatible`. The
[Go model list](https://opencode.ai/docs/go/) has the ids. Every agent step
is one session to Go, so its turns share the prompt cache.
  </Tab>

Set `agents: { default: agent }` in `e2e.config.ts`. Choose a model
available to your account.

## Pick a model

The constructor takes the id the vendor uses, which is not always the name
the app shows. Ask the vendor which ids your login serves:

<CodeGroup>
```bash npm
npx e2e models            # every stored login
npx e2e models openai     # one provider
```

```bash pnpm
pnpm exec e2e models            # every stored login
pnpm exec e2e models openai     # one provider
```

```bash bun
bunx e2e models            # every stored login
bunx e2e models openai     # one provider
```
</CodeGroup>

Each line is the id to pass to `chatgpt()`, `copilot()`, or `grok()`, the
vendor's display name, and what it says about the model: reasoning levels,
vision, preview, or hidden. ChatGPT lists what the Codex backend serves your
plan; Copilot lists the chat models of your plan; SuperGrok lists the
language models the token reaches.

Copilot also lists models that `copilot()` cannot call, and marks them:

- `not enabled`: the model is off for your plan. Turn it on in your Copilot
  settings on GitHub, or ask your organization admin if they manage your
  seat.
- `no chat or responses`: Copilot serves the model only over APIs `copilot()`
  does not speak, such as Anthropic's Messages API, so pick another model.

On its first call `copilot()` picks the endpoint from the model's entry in
this same listing: chat completions for most models, Copilot's Responses API
for the ones served only there. When the listing cannot be read, that call
goes over chat completions and the next call reads it again. The Responses
call runs through `@ai-sdk/openai`, so install it beside
`@ai-sdk/openai-compatible` to use those models; `e2e init` adds both.

## Sign-in help

- ChatGPT opens a browser to sign in. Use `npx e2e login openai --device`
  to sign in with a device code instead.
- Copilot reuses your GitHub CLI login. If you do not use `gh`, pass
  `--client-id` for your own GitHub OAuth app with device flow enabled.
  Use `--enterprise-url` for GitHub Enterprise.
- SuperGrok prints a device code and the URL where you enter it.

Run `npx e2e login` to choose a provider and see which accounts are signed
in. Run `npx e2e logout` to remove a saved login.

## Saved credentials and CI

Logins are stored in `~/.config/e2e/oauth.json`, or under
`$XDG_CONFIG_HOME`, with file permissions restricted to your user. Tokens
refresh automatically. When a vendor rejects the saved token, or its refresh
token, the run fails with `LOGIN_REQUIRED` and names the
`npx e2e login <provider>` command to run.

Use API keys in CI. `E2E_OAUTH_CREDENTIALS` can supply credential JSON
instead of the local file, but refreshed tokens are not saved back to that
variable. A value containing a rotating refresh token cannot be reused
indefinitely. See [CLI reference](/reference/cli#e2e-login) for all sign-in
options.
