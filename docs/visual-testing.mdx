`toHaveScreenshot` compares what the app shows against a PNG stored next to
the test file. It works on every engine that captures pixels, so one test
checks a browser, an iOS simulator, and an Android emulator.

```ts title="tests/checkout.e2e.ts"
import { test, expect } from 'e2e';

test('checkout looks right', async ({ app, screen }) => {
  await app.open('/checkout');
  await expect(screen).toHaveScreenshot('checkout.png');
  await expect(screen.getByRole('button', { name: 'Pay' })).toHaveScreenshot('pay-button.png');
});
```

`expect(screen)` compares the whole screen; `expect(locator)` compares the
box of its one match, scrolled into view first.

## Stored screenshots

The first run has nothing to compare against: it writes the screenshot and
fails. Review the image, commit it, and run again.

```text
tests/checkout.e2e.ts
tests/checkout.e2e.ts-snapshots/checkout-web-darwin.png
tests/checkout.e2e.ts-snapshots/checkout-ios-darwin.png
tests/checkout.e2e.ts-snapshots/pay-button-web-darwin.png
```

Each target and operating system keeps its own file, since fonts and
rendering differ between them. A screen that renders on Linux in CI needs its
screenshots written on Linux: run the suite once in the same environment, or
in CI, and commit what it wrote. Without a name, the screenshot is named
after the test: `checkout-looks-right-1.png`.

When the app changes on purpose, rewrite the screenshots that differ:

<CodeGroup>
```bash npm
npx e2e run --update-snapshots
```

```bash pnpm
pnpm exec e2e run --update-snapshots
```

```bash bun
bunx e2e run --update-snapshots
```
</CodeGroup>

## When it fails

The matcher takes screenshots until one matches or the assertion timeout
(`assertionTimeout`, 5 s) runs out. On a mismatch the failure says how many
pixels differ, and the step keeps three images in the test's results:
`-expected`, `-actual`, and `-diff`, with the changed pixels in red. A screen
that never holds still for two screenshots in a row fails too, with the last
two attached.

## Tolerance and masks

```ts
await expect(screen).toHaveScreenshot('dashboard.png', {
  maxDiffPixelRatio: 0.01,
  mask: [screen.getByTestId('last-updated')],
});
```

| Option | Default | Meaning |
| --- | --- | --- |
| `threshold` | `0.2` | How far one pixel's color may drift and still count as the same, 0 to 1 |
| `maxDiffPixels` | `0` | How many pixels may differ |
| `maxDiffPixelRatio` | `0` | What share of the pixels may differ, 0 to 1 |
| `mask` | none | Locators painted over before comparing, for content that changes between runs |
| `maskColor` | `#ff00ff` | Color of the mask boxes |
| `timeout` | `assertionTimeout` | Assertion budget in milliseconds |

On the web, animations are stopped and the text caret is hidden. On iOS and
Android, the status bar is held in a fixed state, so the clock and battery
read the same on every run.

Secure fields are masked in every screenshot, and after a test fills a
secret the matcher fails with `POLICY_DENIED`, like every other screenshot.
